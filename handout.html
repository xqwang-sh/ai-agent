你要解决的是什么问题？

想象你要给读者一页业绩简报：他要看见收入、利润、同比、来源和还不知道的部分，也要能回到原始材料复查。先看现场 Product 卡，再用 OpenCode + 大模型把它做出来。

本次练习的完成标准

文件版 Product 能生成一页候选简报，三轮 Prompt 有记录，五个 Evals 能逐行运行；证据不足时标成错或待测并留下原因。UI 网页只作为最后的选做展示层。

使用者

需要快速阅读业绩变化的金融教师。

输入

本期、上年同期、单位、指标、来源和不确定项。

输出

一页简报、变化率、来源说明、未知项和通过 / 错 / 待测状态。

先认识三个词

你不需要先记住术语。把它们看成三个连续的问题：我们要交付什么？可以怎样做？怎样知道它变好了？现场先看 Product，再在 OpenCode 中把这三个问题变成文件。

产品

这里的 Agent 先是一条可复刻的产品流程：模型读文件、写文件、按 Prompt 工作，固定案例检查结果，失败就停在当前文件。网页只是最后的展示层。

Approaches / 做法

把五个 Evals 和停止条件写进 Prompt 与运行记录，只为失败项增加规则。

Evals / 评测

五个评测分别检查数字、累计口径、单位换算、来源冲突和能力边界。每次只运行一个 Approach 行，状态只写通过、错或待测。

一次 Chat

一次 Chat 可以很快写出一版文字，但它通常不会替你保留输入、原始回答、评测记录和停止原因；在 OpenCode 中打开工作文件夹，才能把这些产物留下来。

一个有边界的产品

这里的 Agent 先是一条可复刻的产品流程：模型读文件、写文件、按 Prompt 工作，固定案例检查结果，失败就停在当前文件。网页只是最后的展示层。

五个小测验先写通过条件

每个案例只问一个容易出错的问题。你会先写“什么算通过”，再观察输出是否满足；评测结果由案例和证据决定，不由模型自己宣布。

案例输入情境通过条件
数字控制两份来源一致，收入 1000 对 800同比公式正确且保留两位小数
累计口径H1 与 Q1 同时出现说明 H1 是六个月累计，不生成未经来源支持的单季 Q2
单位换算万元与亿元混用写出换算因子并统一单位
来源冲突两份来源给出不同数值标记 conflict，停下并保留待复核
能力边界没有共识或公告原文不写 beat/miss、surprise 或确定性原因
有一个案例故意会停下：如果两份来源冲突，状态写成错或待测，并保留冲突证据；不要为了全绿而改输入。

这段提示词是可选的；先读懂本步的目的，再决定是否粘贴。

请在 OpenCode 中读取同一份 data/evals/teaching_input.json，按下面三轮运行，不要换输入，不要联网，也不要覆盖上一轮结果。把 Prompt、原始回答和观察写入 workflow/minimal/：

01_direct.md：让模型直接写一页简报，记录它怎样处理同比、单位和未知项。
02_schema.md：要求严格 JSON，字段固定为 period、unit、metrics、calculation、unknowns；缺字段就写错，不要自行补值。
03_checked.md：在严格字段之外，要求所有同比写出 current、prior 和公式；遇到来源冲突、单位不明或没有共识时只能输出 UNKNOWN，并列出停止原因。

每轮都记录：使用的模型、Prompt、原始输出、发现的差异和下一轮只改了什么。把比较结论写到 workflow/minimal/approaches.md。先不要做网页；完成后停止。

这段提示词是可选的；先读懂本步的目的，再决定是否粘贴。

请在 OpenCode 中读取 data/evals/teaching_input.json、workflow/minimal/ 三轮输出和 product_spec.md，建立并运行五个最小评测。把案例保存为 data/evals/cases.json，把通过条件保存为 data/evals/expected.md，把结果保存为 data/evals/eval_report.md。

固定五个案例：
1. control：两份来源的本期和上年同期一致，收入同比应为 25.00%；
2. cumulative：H1 是截至 6 月 30 日的六个月累计数，不得把 H1 减 Q1 写成未经来源支持的单季 Q2；
3. unit：一份来源用万元、另一份用亿元，写出换算因子再比较；
4. conflict：两份来源数值冲突，必须停止下结论并保留冲突记录；
5. boundary：没有分析师共识或公告原文，不得写 beat/miss、earnings surprise 或确定性原因。

先逐行运行 01_direct，再运行 02_schema 和 03_checked。每张案例卡只写 pass、fail 或 pending，并说明证据。不要为了让结果全通过而修改输入或删除失败记录。完成后停止。
