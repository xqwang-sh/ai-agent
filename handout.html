先看成品怎么用下载实操材料

跟着做出一个能运行的产品

用自己的 OpenCode，搭出与现场产品相同的财报处理 workflow。先看已有结果，再逐步接上本人的模型调用。

完成后你会得到

一个能回放历史结果、接收个人硅基流动 API Key，并按 02 → 04 → 06 运行的本地网页。它提取五项指标的两期原值，换算单位，计算同比，检查通过后展示候选简报。

本讲固定使用比亚迪 002594.SZ 的 2026H1 与 2025H1 案例。输入是已准备好的报告第 60–75 物理页文字窗口，保留逐页边界；H1 指截至 6 月 30 日的六个月累计数。本讲不重新下载 PDF，也不连接同花顺。

这是一个 workflow

这是一个 workflow，也就是由程序规定顺序、传递数据并检查结果的工作流。它包含模型任务和固定计算工具。程序决定哪一步能继续；模型不能自行宣布通过。页面的六行是三个阶段的做法对照，不是六个依次工作的 Agent。

分清编程 Agent、workflow 和运行模型

你使用的编程 Agent

本讲以 OpenCode 为例。把下面的主 Prompt 发给它，让它写文件、启动程序、运行检查和修复。它使用的编码模型由你在 OpenCode 中配置。

你搭出的 workflow

本机运行的网页和后台程序。负责保存本轮结果、检查前序步骤、执行工具和更新页面。做成后，点网页 Run 不需要 OpenCode 代替你逐次传话。

处理财报的运行模型

与现有产品一致，使用硅基流动的 Qwen/Qwen3.5-4B。网页填写的个人 Key 用于这个模型，与 OpenCode 的编码模型授权分开。

下一步究竟读取哪一份结果？

历史查看与本次运行各有一条链。历史收据可以用来学习和对照，不能补进本轮 Run。在线 Run 和你搭建的本地版本都要遵守下面的依赖。

五项 Evals 检查什么

  1. 1．章节定位检查财务报告章节名和起始物理页。
  2. 2．表格定位检查合并利润表、完整表页及续页、两期列头和原单位。
  3. 3．原值提取五项指标 × 本期与同期，共十个原值；缺失不能当成 0。
  4. 4．单位换算两期都检查；金额转亿元，EPS 保持元/股。
  5. 5．同比计算逐项检查五个同比、两位小数与百分号。

02 完成前三项，04 增加第四项，06 增加第五项。尚未执行的项显示待检查。五项检查是固定案例的程序评测，不等于完成第二讲的独立视觉与外部数据核验；候选简报仍需人工复核。

先在成品中走一遍

先打开现场产品的 Evals。看历史不需要 Key，真实 Run 使用本人的 Key。没有 Key 时，先完成历史查看和后面的离线搭建。

  1. 打开现场产品，先在 Product 看标为“历史计算样例”的表格。此时没有发生模型调用，也不需要 Key。
  2. 进入 Evals，选择“历史结果”，依次点击 02、04、06 的行，查看每行收据与五项检查。再看 01、03、05 的对照结果。03/04 沿用历史 02，05/06 沿用历史 04。
  3. 如要实际运行，在 Evals 的个人 API Key 输入框填写自己的硅基流动 Key。点击 02 的 Run，等待结束；确认章节、表格和十个原值都通过。未通过时先看该行收据，不继续。
  4. 点击 04 的 Run。确认两期换算通过，再点击 06 的 Run。不要跳过前序。每行 Run 都使用本轮真实前序，不从历史收据借输入。
  5. 06 通过后回到 Product，确认标识变成“本次五项检查通过 · 待人工复核”。按需下载当前收据，完成后清空 Key。切回历史查看，不会把历史记录变成本次结果。

历史 01 与 02 的任务和提示词不完全相同，02 曾加入章节、页码和单位线索，不能把历史差异都归因于 thinking。现在的在线 01/02 使用相同任务与字段，只改变 thinking。历史 05 按现有规则复算为 2/5；这是那次运行的记录，不预设老师本次一定会得到同样的成功或失败。

个人运行 Key 在硅基流动控制台管理。只填在网页的隐藏输入框，不发给编程 Agent。网页刷新会清空 Key 和本轮可用前序。
