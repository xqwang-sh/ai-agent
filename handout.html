你要解决的是什么问题？

金融教师要的不是一段看起来像分析的文字，而是一页能回到报告原文的收入与利润简报。demo 把这件事拆成定位、原值、单位、同比和证据边界；讲义把每一段连接成可重跑的 workflow。

本次练习的完成标准

同一份完整报告窗口能产出 raw_values、unit_values 和 yoy_values；五个 Evals 有固定通过条件；验证收据为 verified 后才写候选简报和候选 PPT。失败证据保留，人工复核事项单独列出。

使用者

需要快速阅读业绩变化的金融教师。

输入

本期、上年同期、单位、指标、来源和不确定项。

输出

一页候选简报、变化率、来源说明、未知项和通过 / 错 / 待测状态。

产品

Approaches / 做法

直接换算，真实 API 只过 1/5。

Evals / 评测

工作步骤

加单位门禁：先看无工具失败，再调用 `convert_units`

你愿意把单位换算交给一个可复算的函数，而不是相信模型口算吗？

先做什么

demo 的第三、四行说明单位换算不能只写在自然语言里。先让模型直接换算，保留 1/5 的失败；再提供一个只做换算的工具，把五项逐一交给工具并固定检查返回值。

为什么这样做

`workflow_state.raw_values` 的金额是千元，展示单位是亿元，所以金额除以 100000；EPS 保持元/股。源文件交叉核对时，千元也可以乘以 1000 统一到元。两种换算方向要在字段里写清，不能混用。

固定实现示例

这段代码说明本步的固定边界。把它放进项目时，保留真实路径和收据字段。

UNIT_TOOL = {
    'type': 'function',
    'function': {
        'name': 'convert_units',
        'description': '千元金额换算为亿元；EPS 元/股保持原值',
        'parameters': {
            'type': 'object',
            'properties': {
                'metric': {'type': 'string', 'enum': METRICS},
                'current': {'type': 'number'},
                'prior': {'type': 'number'},
                'source_unit': {'type': 'string'},
            },
            'required': ['metric', 'current', 'prior', 'source_unit'],
        },
    },
}

def convert_units(metric, current, prior, source_unit):
    if metric == 'basic_eps':
        return {'current': current, 'prior': prior, 'unit': '元/股'}
    assert source_unit == '千元'
    return {
        'current': round(current / 100000, 2),
        'prior': round(prior / 100000, 2),
        'unit': '亿元',
    }

messages = [{'role': 'user', 'content': unit_prompt(raw_values)}]
for _ in range(8):
    reply = chat(messages, tools=[UNIT_TOOL], tool_choice='auto')
    calls = reply.get('tool_calls', [])
    if not calls:
        final = parse_json(reply['content'])
        break
    for call in calls:
        result = convert_units(**call['arguments'])
        messages += [call, {'role': 'tool', 'tool_call_id': call['id'], 'content': json.dumps(result)}]
assert grade_units(final) == '5/5'
write_json('workflow/runs/unit-tool.json', {'workflow_state': {'unit_values': final}})

工作步骤

加同比门禁：先保留四舍五入错误，再调用 `calculate_yoy`

当一个百分比只差 0.01 个百分点时，你怎样让课堂看见它确实错了？

先做什么

第五、六行只使用已经通过单位门禁的 `workflow_state.unit_values`。先看无工具的 4/5，再让 `calculate_yoy` 固定分母、精度和百分号格式。

为什么这样做

金融课堂里一个同比小数位的差异会影响学生对结果的信任。工具把公式固定为 `(current - prior) / prior * 100`，保留两位小数；程序把每个指标的结果与门禁值逐项比较。

固定实现示例

这段代码说明本步的固定边界。把它放进项目时，保留真实路径和收据字段。

def calculate_yoy(metric, current, prior):
    if prior == 0:
        raise ValueError(f'{metric}: prior is zero')
    value = (current - prior) / prior * 100
    return f'{value:.2f}%'

for metric, pair in unit_values.items():
    tool_result = calculate_yoy(
        metric=metric,
        current=pair['current'],
        prior=pair['prior'],
    )
    yoy_values[metric] = tool_result

EXPECTED_CHANGE = {
    'revenue': '-7.13%',
    'operating_cost': '-8.08%',
    'operating_profit': '-21.24%',
    'parent_net_profit': '-20.54%',
    'basic_eps': '-21.05%',
}
assert yoy_values == EXPECTED_CHANGE
write_json('workflow/runs/yoy-tool.json', {
    'workflow_state': {'source_step': 'yoy-tool', 'yoy_values': yoy_values},
})

workflow/runs/yoy-baseline.json、workflow/runs/yoy-tool.json。下一步的简报只能读取通过的 `yoy_values`。

本步结果

你会看到“无工具 4/5 → calculate_yoy 5/5”。这一步把一个看似很小的四舍五入差异变成可教学、可复跑的门禁。

把模型输出交给固定检查，再生成候选简报

怎样让模型不能用一句“看起来正确”跳过财务核对？

先做什么

前面的模型输出还不是交付物。固定程序要重新检查身份、报告期、章节、表格、十个原值、单位、五个同比、来源和证据状态，只有通过才写候选简报。

为什么这样做

把“通过”定义成代码条件。收据里同时保存输入状态、实际工具调用、每项 expected 与 got、失败原因和下一步。出现身份、单位、来源或数值冲突时，阶段标记为 blocked，后续阶段保持 pending。

固定实现示例

这段代码说明本步的固定边界。把它放进项目时，保留真实路径和收据字段。

REQUIRED = ['section', 'table', 'raw_values', 'unit_values', 'yoy_values']

def fixed_gate(states):
    checks = []
    for name in REQUIRED:
        checks.append({'check': name, 'state': state_ok(states[name]), 'evidence': evidence_for(name)})
    if all(item['state'] == 'pass' for item in checks):
        return {'status': 'verified', 'checks': checks}
    return {
        'status': 'blocked',
        'checks': checks,
        'failure': {'next_action': next_failed_check(checks)},
    }

receipt = fixed_gate(load_states())
write_json(run_dir / 'verification_receipt.json', receipt)
if receipt['status'] != 'verified':
    mark_current_stage('blocked')
    raise SystemExit('BLOCK: repair the failed check before writing the candidate brief')
write_candidate_brief(states, status='草稿——需要人工复核')

工作步骤

最后拼起来：让四个 Agent 共享状态，固定程序决定放行

怎样把一次课堂演示变成下一次仍然可审计的运行？

先做什么

现在把前面的正确步骤放进可重复运行的工作流。四个 Agent 负责取得证据、计算、原文复核和撰写简报；共同 Skill 规定金融口径；固定控制器记录阶段、调用验证器，并决定候选 PPT 能不能更新。

为什么这样做

编排器只连接步骤，不替代门禁。每一步先写 running，完成后写 completed；失败写 blocked，后续不启动。固定验证器只读取本次运行目录，收据为 verified 后，PPT 更新阶段才消费计算表和核对表。
