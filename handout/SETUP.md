# 第一讲准备工作

这份讲义按没有编程基础的老师来写。程序由 OpenCode 写，你负责逐条发请求、打开网页和核对结果。先读 [教师实操讲义](../handout.html)，不要直接把全部提示词一次发出去。

## 1. 先分清三个画面

| 画面 | 在这里做什么 |
| --- | --- |
| 讲义与线上参考成品 | 读步骤、复制 Prompt、看历史样例。这里不是你正在写的程序。 |
| OpenCode 桌面软件 | 打开自己的材料文件夹，在同一会话逐条发送 Prompt，让它写文件、检查和启动程序。 |
| Agent 返回的本机网页 | 地址通常以 `http://127.0.0.1` 开头。这里才是你做出的练习，最后在这里填写个人 Key、点 Run。 |

Prompt 是发给 OpenCode 的任务说明。Product 看简报，Approaches 看做法，Evals 看每行运行与检查。Node.js 是程序运行所需的环境，第 0 步让 Agent 检查，不用先学它的命令。

## 2. 准备能回复的 OpenCode

本轮实际跟做使用 macOS 上的 OpenCode Desktop 1.18.26。已有能工作的桌面版就继续用，不必更换版本。

1. 尚未安装时，打开 [官方下载安装页](https://opencode.ai/download)，找 **OpenCode Desktop**，按自己的系统下载安装。不要把 Terminal 的安装命令当作本讲必做步骤。
2. 打开软件，确认输入框附近能看到一个编码模型名称。若已能回复，直接进入下面的材料准备。
3. 尚未连接时，先在 OpenCode 的模型连接入口配置自己使用的编码模型授权。参照与你安装版本对应的 [官方文档](https://opencode.ai/docs/) 和 [提供方连接说明](https://opencode.ai/docs/providers/)。终端版的 `/connect`、`/models` 是另一种界面，不要求桌面版初学者先打开终端。
4. 在输入框发送“请回复一句‘可以开始练习’，先不要写文件”。收到正常回复后，再开始第 0 步；若模型连接仍报错，先解决连接，不要继续复制搭建 Prompt。

两项授权分开准备：

| 用途 | 填写位置 | 什么时候需要 |
| --- | --- | --- |
| 让 OpenCode 帮你写程序 | OpenCode 自己的模型连接界面 | 发送第 0 步之前 |
| 让做出的程序处理财报 | 本地网页 Evals 的个人硅基流动 Key 输入框 | 第 7 步真实 Run 时 |

API Key 是服务控制台创建的调用凭据，不是账号登录密码。OpenCode 能回复，不代表本地财报程序已经有硅基流动授权。

准备财报运行 Key 时，由本人操作：

1. 登录 [硅基流动控制台](https://cloud.siliconflow.cn/)，进入“API 密钥 / API Keys”。
2. 已有可用 Key 就复制该 Key；尚未创建时，点“新建 API 密钥 / Create API Key”，按页面提示创建后复制完整密钥。
3. 回到自己做出的网页，等第 7 步程序定稿后，粘贴到 Evals → 本次运行的隐藏输入框。Key 不发给 OpenCode。

按钮名称可对照 [硅基流动官方快速上手](https://docs.siliconflow.cn/docs/userguide/quickstart)中的“创建 API Key”一节。注册、登录和创建由本人完成；没有可用 Key 时，先完成离线搭建，把真实 Run 保留为待完成。


## 3. 下载、解压，再选择正确目录

1. 下载 [第一讲实操材料](../lesson-one-materials.zip)。在电脑“下载”文件夹找到 `lesson-one-materials.zip`。
2. macOS 双击解压；Windows 右键选择“全部解压缩”。先放在本机可写的下载目录中练习，不在压缩包或附件预览里操作。
3. 用 Finder 或资源管理器打开解压后的 `earnings-workflow`。看到下列文件后再继续。若眼前只有另一个同名文件夹，就再向内打开一层。

```text
earnings-workflow/
  TASKBOOK.md
  AGENTS.md
  data/report-pages-60-75.txt
  contracts/workflow.json
  prompts/runtime/
  history/lesson-one-history.json
  checks/
```

4. 在本次实测的 OpenCode 桌面界面，点击输入框下方的当前项目名 → **添加项目** → 选择这个 `earnings-workflow` → **打开**。
5. 等项目名变成 `earnings-workflow`，进入本项目的一个会话。后面的第 0–7 步都在这个会话继续。其他版本若提供“打开项目”或“打开文件夹”，选择同一个目录。

OpenCode 只显示聊天而没有文件列表也正常。第 0 步会让它列出真实目录与文件，替你确认位置。材料包没有网页程序；现在不能直接打开一个成品，是正常状态。

本轮实际遇到同步目录变成只读、写文件失败的问题。若出现 `PermissionDenied`、`EACCES` 或“无法保存”，不要猜系统权限命令。用第 0 步修复 Prompt，让 Agent 说明如何换到本机可写的新目录，再重新打开项目。

## 4. 每一步怎样发送和核对

1. 点讲义本步“发给 OpenCode”右侧的 **复制 Prompt**。
2. 回 OpenCode，点底部大输入框粘贴。macOS 用 Command+V，Windows 用 Ctrl+V。点右下角 **发送** 或纸飞机。
3. 等它给出本步结果。写程序可能要数分钟到十多分钟，以本步完成回复为准。还有“思考中”或“停止”按钮时，先不要连发下一步。不要把修复 Prompt 和下一条主 Prompt 一起发送。
4. 按讲义“你应看到”核对。文件由 Agent 保存；不要求你先读代码、JSON 或日志。
5. 只给方案、没有生成文件或地址时，发送本步修复 Prompt，让它实际写文件和检查。若它明确提示当前是只规划的 Plan 模式，先按该版本的模式入口切到允许编辑的 Build，再继续。

本轮还实际遇到“需要权限：访问项目目录之外的文件 /tmp/*”，使 Agent 停住。若出现这一提示，点“拒绝”，然后发：“请把临时检查输出放在当前项目内，不访问项目外目录，继续本步检查并给我结果。”等待授权不等于本步已完成。

第 0 步检查 Node.js 22 或更高版本、材料和写入权限。缺少环境时让 Agent 给出适合当前系统的安装步骤，安装完成后发送“已安装，请重新检查”。官方环境入口为 [Node.js 下载页](https://nodejs.org/en/download)。

## 5. 怎样启动、关闭和重新打开网页

第 1 步由 Agent 替你启动程序，并回复实际可点击的本机网址。示例端口不是固定要求，以它真正启动后给出的地址为准。不要双击 HTML 文件，也不用自己找终端或进程编号。

以后在同一项目中，向 OpenCode 发普通中文请求：

- 启动：“请读取 RUN.md，替我启动当前练习，确认可访问后给我完整网址，不重复启动。”
- 改过后台但网页没变：“请停止本项目旧服务后重新启动，只保留一个实例，给我更新后的完整网址。”
- 结束：“请按本项目启动记录停止本练习服务，确认已停止，不关闭其他项目。”

完整可复制文本在讲义第 1 步的“以后怎样启动、停止、重新打开”中。`RUN.md` 也要写出这种操作，不应只留一组命令。

修改后台后，只刷新浏览器不一定生效；先让 Agent 重启，再打开它确认的地址。浏览器刷新会清空本轮可用前序，真实运行要从 02 重新开始。

## 6. 先完成搭建，再一次真实运行

第 3–6 步先由 Agent 写程序、运行离线检查。没有财报 Key 也可以继续。测试响应必须标明测试用途，不能当作本人真实 Run。

第 7 步程序不再改动后，再由本人操作：

1. 打开 Agent 给出的本机网址，点 Evals，再点“本次运行”。
2. 在隐藏输入框填写本人的硅基流动 API Key。同一页面连续运行时无需每行重填；清空 Key 或刷新后需要重新填写。Key 在 [硅基流动控制台](https://cloud.siliconflow.cn/)管理，不发给 OpenCode。
3. 点 02 的 Run，等章节、表格、十个原值检查通过。
4. 点 04 的 Run，等两个期间的单位换算通过。
5. 点 06 的 Run，等五项检查全部通过，再看 Product 的本次候选简报。
6. 回 Evals 的“本次运行”，分别点 02、04、06 的“查看记录”与“下载本次收据”，保存三个文件，再清空 Key。真实调用失败就保留失败，不从历史补输入。

没有 Key 时，将真实运行留为“待本人填写 Key 后完成”；离线检查可以完成，不能把历史或测试成绩写成真实通过。

材料中的历史只读，固定案例参考只供程序评分。个人 Key 只留在页面与本次请求内存，不进入项目、浏览器存储、收据或日志。

## 7. 换电脑时带走什么

本机网址只对这台电脑有效，不能把这个地址发给另一位老师当作线上产品。换电脑时，带走做出的整个 `earnings-workflow` 文件夹，再让对方的 OpenCode 读取 `RUN.md` 检查环境并启动；不能只发一份 `RUN.md`。个人 Key 由对方自己在网页填写。

本轮桌面操作实测为 macOS；Windows 的解压与粘贴写明了对应操作，没有将其标为已完成 Windows 实机验收。
