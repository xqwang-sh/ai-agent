检查不通过，走这条补证分支

  1. 程序保存失败阶段、失败原因与已有进度。
  2. 将这些信息交回同一会话；不提供正确答案、差额或正确页码。
  3. 模型自行检索、读页或重提完整候选，程序仍按相同规则检查。
  4. 文字候选改变后，重新计算，并重新启动独立视觉核验和外部核验。

视觉自身引用失败留在该视觉会话内续跑（在同一次会话里接着上次继续，而不是从头再来）。所有调用共享总预算；达到请求数、tokens（模型读写文字的计量单位，用量和费用都按它统计）、时间的上限，或连续无进展、重复失败，就停止并保存原因。服务或用量异常也会停止，不生成本轮复盘。

每一步具体做什么

步骤谁执行输入、操作与输出
1．PDF 转逐页文字程序每份报告提取一次，保留每个物理页（按 PDF 文件顺序数第几页，封面算第 1 页，与页面上印的页码可能不一样）的完整文字和源文件指纹（用 SHA-256 哈希算法对文件内容算出的一串字符，文件改动一个字它就会变，用来确认文件没被改动），空白页也计数；后续读取同一份快照（一份固定下来、不再变化的副本，之后每次都读它）。
2．生成导航索引程序为每页生成包含页头、单位或指标附近文字的导航卡（每页一小段摘要，模型靠它快速判断该读哪几页，不用翻整份报告）。覆盖所有物理页号，文字有省略，不能直接作为完整财务证据。
3．定位证据页文本模型读取全部导航，判断哪些页包含合并利润表、续表、金额单位和 EPS 单位，返回页码与原文锚点（从原文摘出的一小段文字，程序用它核对模型说的位置真实存在）；需要时自行请求检索全文、读取指定页，由程序执行。
4．读取完整页程序检查页码与锚点是否真实存在，读取所选整页，检查关键线索是否缺失。不通过时记录原因并进入受预算约束的补证，不向模型补入正确页码。
5．抄录原值文本模型读取完整证据页，输出五项指标的两期数字、原单位、年份列头、合并口径与出处。保留括号、负号和引文，不计算。
6．检查来源程序检查字段、引用页、单位原句，以及完整数字是否绑定对应指标行、保留原符号与精度。不通过时保留失败；文字检查通过，也仍需后面的独立核验。
7．换算、计算程序用 Decimal 按原单位换算金额，EPS 保持元/股，用固定公式计算同比；上期不为正时同比不适用。原值与候选计算表分别保存，未核验结果不进入最终复盘。
8．内部视觉核验独立视觉模型＋程序新的视觉会话只看选定原始页图（把 PDF 某一页原样转成一张图片，让视觉模型像人一样“看”这一页）与任务，不看文字答案或同花顺参考值。重新抄录后由程序核对数值、单位和证据，保存内部核验记录。
9．外部数据核验程序＋同花顺取得同一公司、相同累计 H1 口径的两期数据，按 PDF 原单位与披露精度逐项比较。参考数值由程序保管，不进入模型补证反馈。
10．生成网页复盘程序当前版本的两层核验通过后，封存（打包保存并记下文件指纹，之后不再改动，方便日后核对）原 PDF、页图、原值、计算与核验记录，生成财务表、同比、利润率、图表与证据链接。每步模型、tokens、耗时和全部续跑留在同一用量账本（记录这一轮每次模型调用、消耗和耗时的清单）。

本讲已经接通内部视觉核验、同花顺比对和网页交付，这三部分与前面的取证、计算使用同一条实线流程。最终交付是 Earnings Review 网页。

网页将这些操作归到六个运行步骤：读取 PDF、定位证据、抄录与补证、内部视觉核验、同花顺外部核验、生成复盘。逐页文字与导航属于“读取 PDF”；完整读页、来源检查和初步计算主要发生在“抄录与补证”。利润率等展示指标由“生成复盘”读取已核验原值确定性计算。

先分清谁在搭建，谁在运行

你正在使用的编程 Agent

Codex、Claude Code、Cursor、Kimi Code、ZCode、WorkBuddy、Qoder、Trae 等任意一种，或 OpenCode 搭配 DeepSeek。它负责读任务、写文件、启动程序、检查和修复。这里的主 Prompt 都发给它。

做出来的财报 Agent

是你本机的一个程序。它按固定阶段运行，用工具读 PDF，调用财报模型，检查证据并更新网页。

程序调用的财报模型

主线使用 Qwen 27B 做文字抄录和独立视觉复读。它与你的编程 Agent 当前使用的编码模型是两项配置。

固定的是阶段、财务口径、检查规则和停止条件。证据页由模型借助检索和读页工具自行寻找。把程序做出来之后，日常点网页运行不需要编程 Agent 留在对话中。

同一流程在网页中的六个运行步骤

  1. 程序读取 PDF

    检查文件身份，抽取整份逐页文本并生成导航。

  2. 模型＋工具定位证据

    模型选择物理页，必要时检索全文、读取页面。

  3. 模型＋程序抄录与补证

    模型保留原值和单位，程序检查来源并计算。

  4. 视觉模型＋程序内部核验

    新会话盲读页图，程序比较两次独立抄录。

  5. 同花顺＋程序外部核验

    取独立两期数据，按原披露精度逐项核对。

  6. 程序生成复盘

    核验通过后封存证据，计算同比和利润率，更新网页。

做到什么程度算完成
  • 公司列表来自本地真实 PDF；新增一份符合条件的报告，重新扫描就能出现。
  • 点击运行后产生真实任务，六个阶段显示实际状态、模型、tokens 和耗时。
  • 内部核验独立读取原始页图，外部核验与同花顺数据逐项对照。
  • 检查失败时交回失败原因和已有进度；达到预算或无进展条件就停止。
  • 只有当前版本的两层核验都通过，才生成带证据链接的复盘。

  3. 确认编码模型可以工作

    按你所用编程 Agent 的官方文档连接好编码模型，连接后直接从第 0 步开始，不额外发送测试对话。用 OpenCode 时，CLI 的 run 方式使用 --model deepseek/deepseek-flash --variant high；交互界面按本机模型选项切到 High 推理档。若 High 出现无进展、输出上限耗尽、以 length 结束或效果不足，保留该次结果并在全新空项目中改用 Max（CLI 使用 --variant max）重跑，不把两档结果合并为同一次。编码模型和财报运行模型不是同一个配置，财报默认仍是 Qwen27B。
