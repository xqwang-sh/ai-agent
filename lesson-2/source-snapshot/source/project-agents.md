# Earnings Review 项目约定

在本项目从零搭建本地财报复盘程序。主线只有第 0–8 步九条消息；每条消息完成当前步骤、验收和自修后停下。通用规则以本文件为准，本步任务以当前消息为准，数据与接口以 contracts、prompts/runtime、acceptance/README.md 为准。已有上下文不重复展开，按本步需要读取。

## 工作目录与材料

- 每步先从工具输出确认当前项目根目录。优先使用相对路径；必须写绝对路径时，从实际根目录生成并确认父目录存在，不重打或猜测路径。
- 先建 runtime/step-N 和 runtime/step-N/tmp，N 为当前步骤。日志、临时脚本、诊断、试渲染和测试输出只写在本步目录或 tests/output；Python 临时目录显式指定项目内 dir，不使用 /tmp、系统临时目录或其他项目，不请求项目外写入权限。
- 只使用本次材料及本项目新写的代码，不读取或复制其他项目、历史成品、已有财报任务或讲义外观察文件。保留公开 acceptance、contracts、四份运行时提示词与本文件的约定；不能改断言、跳过检查或另造测试专用成功路径。
- reports 是完整真实 PDF 输入；prompts/runtime 是程序发送给财报模型的指令，不是当前开发任务。先校验 MATERIALS.json 的 PDF、运行时提示词、验收与项目规则哈希，差异先报告。
- 适配实际操作系统，使用最少依赖：Python 后台、原生 HTML/CSS/JavaScript 前台。端口冲突时另选空闲端口，或只停本项目有记录的自有进程。权限被拒、空回复、length 或退出码 0 均不等于完成。

## 分段开发

按「最小生产修改 → 编译 → 检查 → 按失败局部读源」循环，在同一条消息内自动继续。每段先实际写入再分析下一段，不在首次写入前推演完整产品；缺的未来能力明确未实现，不能伪造成功。更新 project_status.md 时将九个开发步骤与六个运行阶段分开。

第 5 步首写检查点：首次业务写入前禁止读取acceptance测试体或 fixture。最多两次必要接口读取，工具回传正文合计不超过6000字符，只读现有生产接口、observation.schema 或本步 runtime 提示词必要片段。立即在 app/contracts.py、app/extract.py 写出能识别合法单 JSON、完整单围栏和非法传输的最小可执行实现，编译后立即运行through5，取得真实失败。目录、文档、注释、pass 或纯占位不算首写。随后按失败逐段补协议、来源绑定和生产循环，最终全部11项公开检查及本地检查须通过。

取得真实失败后，每轮只读一个相关测试定义或 fixture helper 的必要局部，以 80 行和 4000 字符为参考目标；更长时记录实际读取范围。先修生产、编译和复测，再展开下一个问题，不连续拼读整份源码。这些是开发工具回传限制，不限制财报证据、metadata 链或来源绑定距离，不另设第二道期间首写门槛。

## 每步验收与完成条件

使用本项目 Python，N 为当前步骤：

1. 执行 `python -m acceptance.checks --through N`。
2. 待其完全结束，再执行 `python -m acceptance.local_checks --output runtime/step-N/local-checks`；第 0 步只运行公开环境检查。

两者严格串行。公共冻结/canary 会暂时改写并恢复工作区，不能与其他冻结、本地检查或合成任务并行。先建 tests/__init__.py；默认本地入口在发现或导入测试/应用之前安装公开离线守卫并设置项目内临时目录，不以裸 unittest discover 或 tests/__init__.py 副作用代替。Python 子工作进程继承守卫，只允许回环合成传输。

完整日志保留在 runtime/step-N。公开命令只将 stderr 写入本步日志，stdout 中真实 JSON 回执原样回传，并保留同一次调用的退出状态；本地检查也保留完整日志与原始结果，不截断、改写或用后一次输出冒充本次结果。失败时自行读日志、修通用代码并重测，不等待另一条修复、恢复或观察消息。

通过后把完成证据和未解决问题写入 project_status.md，再返回并停下。缺授权或环境确实无法继续时，明确阻塞和已完成部分。累计公开检查数为 1、1、3、6、6、11、16、35、35；第 6 步已有完整合成成功链，第 7 步完成全部生产接线，第 8 步做网页与启动验收。

## 同一个生产程序

- 逐步扩展同一 TaskManager、冻结 TaskRunner、WorkflowController 和 server 工厂；project_root/runtime_root 显式传入。app/acceptance.py 仅适配实际生产接口，serve/run 使用正常 server、TaskManager 与新冻结 worker，只注入合成身份和回环传输，不替换编排、_spawn、计算或封存。
- 每个任务独立保存 PDF、源码、提示词、配置和逐文件哈希，原子发布冻结目录。新 Python 子进程从本轮 program 执行，调用前校验实际源码及 PDF；运行中不换模型或修改快照。允许清单包含 prompts/runtime 输入，排除根目录 runtime 输出、凭据、.git、缓存、软链接和路径穿越。
- StageJournal 持久记录递增 sequence、stage、start/end、Unix 秒 at，end 含 outcome。进入阶段先落 start，结束、失败、中断和恢复配对落 end；重入保留独立区间，终态不再增加耗时。任务投影由真实 state、ledger、journal、proof 生成，不能另算一套财务结果。
- 创建任务校验证券身份、当前源哈希与服务就绪；复制 PDF 后再校验哈希。只允许一个活动任务，同一启动意图的幂等键返回同一任务，新显式运行使用新键；GET、历史、刷新和公司切换只读。候选变更仅使当前证明失效，不清终身进度和预算。
- 原始请求/响应、工具动作、所有候选、逐页文字、实际已发页图、完整参考和执行记录都留存。每次可解析文字 submit 先保存独立候选，再过关卡；封存包含真实文件及哈希，封存成功后才发布 candidate_ready。未通过当前两层检查时 review 为空，旧成功只在标明历史的区域显示。

## 财务与核验

- 目标是 A 股 2026H1 对 2025H1、人民币合并报表，五指标为营业收入、营业成本、营业利润、归母净利润、基本每股收益。区分收入/总收入、成本/总成本。模型找证据和抄录，程序计算、核验、计费和决定停止。
- 保存原值字符串、完整数词位置、原单位、行名、两期列头、物理页与逐字引文。文字与视觉共用一个生产绑定器和闭合期间/单位判定，按 contracts/workflow.json 的完整表达及表块归属规则证明，不按关键词、子串、固定距离或缺省值放行；歧义或缺证据就失败补证。具体正反例由公共验收强制。
- 金额以未舍入 Decimal 规范值计算，最后 ROUND_HALF_UP 展示两位亿元；EPS 保持元/股，不套金额倍率。成本使用正费用幅度，原始符号与规范化依据留在 review.normalizations，含 current_signed_yuan/prior_signed_yuan 与精确幅度。同比上期不为正时为 null；利润率按任务书公式，不从展示值重算。
- review 只生成一份规范投影，字段遵守 workflow.json.review_projection；不生成 review.summary 或 review.series 金额副本。web/task-view.mjs 的 reviewCards(review) 仅按准确指标 ID 选择收入、归母净利润和毛利润，毛利润取 gross_profit；实时、刷新、历史都使用它，不做另一套计算。
- 独立视觉会话只接收实际选定原 PDF 整页图、物理页标签、身份与期间，不含文字候选、转录、文字历史或外部答案。保存实际图片哈希和候选版本；视觉自身修订留在该会话，文字或页包变化则旧证明失效并新建盲读会话。
- 外部参考仅程序可见。使用本机 hithink-finance 当前 schema：能力 ID 是 financials.income，查询 argv 是 financials income；唯一筛选两个目标年的 Q2 累计 H1，完整季度 envelope 原样保留。身份、日期、币种、期间和数值精度按公共契约核对，不能用参考值、差额、正确页码或查询词给模型补答案。
- 按 workflow.json 的同一动作分派、预算、终身最好规则和停止条件处理来源、视觉与外部反馈；检索/读页不等于进展。所有初始与续跑调用共用账本，完整 usage 才可知，pending 与 unknown 区分并与已知小计并列；unknown 停止后续准入，中断先确认 worker 停止再逐条收尾，不补零或重置计数。
- 不写无证据的经营原因、分析师预期、估值或投资建议；交付仍标待人工复核。

## 授权与模型

OpenCode 参考编码配置为 Build、deepseek/deepseek-flash、High 推理档，CLI 使用 `--variant high`；默认输出上限沿用当前工具，不启用隐藏覆盖。High 无进展、以 length 结束或效果不足时，保留记录，在全新空项目用 Max 重跑，CLI 为 `--variant max`，不合并两档证据。记录实际版本和差异，编码模型与财报运行模型分开。

财报凭据优先进程 SILICONFLOW_API_KEY，否则读取 macOS/Linux 的 ~/.config/siliconflow/credentials.env 或 Windows 的 %APPDATA%/siliconflow/credentials.env。只检查非空和文件权限；Unix 限本人读写。缺失时给出本机隐藏输入方法，等待用户配置；密钥不进入项目、网页、聊天、命令参数、请求回执或日志，不读取 OpenCode 私有登录文件冒充程序授权。同花顺也使用用户自己的认证。

默认开发检查不发真实财报生成或利润表请求。第 2 步用户明确扫描时可做真实证券身份确认，第 4 步可单列模型列表预检；不得在导入、轮询或默认测试中触发。编码完成、离线合成通过、预检就绪与真实财报通过分别记录。第 8 步启动服务并停在用户手动点击之前。

## 网页与浏览器

网页仅访问本机后台，后台监听 127.0.0.1，变更请求核对 JSON 与同源 Origin，证据只经允许的任务路由，不暴露任意本地文件。任务接口、createTaskView、恢复/晚到响应和只读历史按 acceptance/README.md 实现；以报告 ID 与源 PDF 哈希绑定，使用任务冻结模型，不用当前下拉框覆盖历史身份。

沿用米白 #eff0e4、纸白 #fafaf2、深灰 #202328、雾蓝 #7899c4、珊瑚红 #bb5b4e、鼠尾草绿 #668f6c，不加载外部字体或脚本。1280/375/320 宽度可读，窄屏单列、长路径和模型名换行，阶段名称保持横向，根页面不横向溢出。进度、用量、失败与历史均来自当前真实任务，不用假数字、倒计时或旧绿灯。

浏览器检查使用当前 Agent 已获准使用的工具，不另装浏览器自动化栈或启动 Chrome 远程调试/CDP。没有工具时完成 HTTP/API 与离线检查，启动服务并给出网址和明确人工步骤，将浏览器项标待实际检查。静态、Node、HTTP、浏览器与真实财报检查各自证明自己的范围，不能互相冒充。
