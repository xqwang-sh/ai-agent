# 用自己的 Agent，搭建 Earnings Review

第二讲 · 教师实操讲义

本讲假设你已经安装 OpenCode。接下来每次复制一条 Prompt，让自己的编程 Agent 写出一部分程序、运行检查，再由你核对结果。完成后，用户只需要选公司、选模型、点运行，就能看到进度、两层核验和公司的半年报 Earnings Review。

## 分清三个角色

- 你正在使用的编程 Agent：例如 OpenCode。它负责读任务、写文件、启动程序、检查和修复。这里的主 Prompt 都发给它。

- 做出来的财报 Agent：是你本机的一个程序。它按固定阶段运行，用工具读 PDF，调用财报模型，检查证据并更新网页。

- 程序调用的财报模型：主线使用 Qwen 27B 做文字抄录和独立视觉复读。它与 OpenCode 当前使用的编码模型是两项配置。

固定的是阶段、财务口径、检查规则和停止条件。证据页由模型借助检索和读页工具自行寻找。把程序做出来之后，日常点网页运行不需要 OpenCode 留在对话中。

## 完成标准

- 公司列表来自本地真实 PDF；新增一份符合条件的报告，重新扫描就能出现。
- 点击运行后产生真实任务，六个阶段显示实际状态、模型、tokens 和耗时。
- 内部核验独立读取原始页图，外部核验与同花顺数据逐项对照。
- 检查失败时交回失败原因和已有进度；达到预算或无进展条件就停止。
- 只有当前版本的两层核验都通过，才生成带证据链接的复盘。

## 最终六阶段

- 读取 PDF · 程序：检查文件身份，抽取整份逐页文本并生成导航。

- 定位证据 · 模型＋工具：模型选择物理页，必要时检索全文、读取页面。

- 抄录与补证 · 模型＋程序：模型保留原值和单位，程序检查来源并计算。

- 内部核验 · 视觉模型＋程序：新会话盲读页图，程序比较两次独立抄录。

- 外部核验 · 同花顺＋程序：取独立两期数据，按原披露精度逐项核对。

- 生成复盘 · 程序：核验通过后封存证据，计算同比和利润率，更新网页。

## 准备项目

材料包只有六份完整 2026 半年报、任务书、数据约定、合成检查案例，以及四份通用运行时提示词。没有成品程序、预填的财务结果、预选页码或 API Key。

1. 准备一个新项目。新建名为 earnings-review 的空文件夹。下载并解压实操材料包，把包内 earnings-review 文件夹里的内容放进这个项目。确认 reports 下面有六份 PDF，contracts 和 prompts 也在项目根目录。

2. 让 OpenCode 打开这个文件夹。使用你已安装的 OpenCode 打开 earnings-review。在输入框中发送下面第 0 步的 Prompt。后续始终在同一个项目里操作。若只给方案不写文件，检查是否处于允许编辑的 Build 模式。

3. 确认编码模型可以工作。先让 OpenCode 正常回复一句话并读取当前项目。如果尚未连接模型，在它的连接入口完成配置；终端版常用 /connect 和 /models。具体界面以你安装的版本为准，不要求换装另一版本。

4. 准备程序运行所需的服务。财报模型的服务端 API 凭据，以及同花顺金融数据服务凭据，需要单独确认。OpenCode 能聊天，不代表生成的程序能读取同一项授权。第 0 步会检查缺什么，并给出适合你电脑的配置方法。 暂无服务凭据时，可以先搭建离线模块；第8步真实运行前必须补齐，不能把未完成写成通过。

每步按同一方式进行：复制主 Prompt → 发给 OpenCode → 等待它修改文件并运行检查 → 按本页检查点核对。确认后再发下一步。文件名是共同约定，代码由你的 Agent 完成。下方的修复 Prompt 可以原样发送，不需要你先学会分析报错。

## 第1步：把任务和规则写进项目

把“我要一个财报网页”变成后面每一步都能遵守的共同约定。

### 现在怎么做

- 确认环境问题已处理，或已明确哪些步骤会暂时停止。
- 发送下面的 Prompt，让 Agent 建立项目骨架和规则。

### 发给OpenCode

```text

AGENTS.md 要固定这些要求：
- 输入是 reports 中实际存在的 A 股 2026 完整半年报，期间是 2026H1 对 2025H1，口径是合并报表。
- 五项指标为营业收入、营业成本、营业利润、归母净利润、基本每股收益。收入与营业总收入、成本与营业总成本要分清。
- 原值、原单位、列头、取值物理页、单位物理页和逐字引文先保存，后由代码计算。EPS 保持元/股。
- 固定六个阶段：prepare、locate、extract、vision、external、delivery。证据页和查询词不能写死。
- 模型只负责找证据和抄录。程序负责计算、核验、状态转换、累计用量、预算和停止。
- 内部视觉核验用新的独立会话；外部参考值由程序保管，不能交给抄录模型。
- 每次运行有独立目录。失败保留已完成证据，不覆盖此前成功结果。当前两层检查未过，review 必须为空。
- 不做分析师预期、估值、投资建议或没有证据的经营原因解释。
- 所有开发工作留在本项目；密钥不写进项目。

选用最少的依赖：Python 后台、原生 HTML/CSS/JavaScript 前台；先不引入复杂框架、数据库、云部署或 codex exec。项目里的固定程序本身就是运行器。

project_status.md 列出第 0 至第 8 步，每步记录完成证据和未解决问题。当前只初始化骨架，不伪造完成状态。运行一个本地环境检查，给我下一步应看到的文件，完成后停下。
```

- Agent 已创建项目规则与进度文件，保留已有 PDF、规则约定文件和提示词。
- 目录中有 app、web、tests、runtime，仍没有财报分析结果。

- AGENTS.md 写清了编码 Agent 与运行程序的分工。

## 第3步：让程序会读整份 PDF，并提供读页工具

程序先把整份报告整理成带物理页码的文本，模型稍后只拿导航和自己请求的证据。

### 现在怎么做

- 发送本步 Prompt。
- 按 Agent 给出的检查方法，查看一份逐页文本文件和一张渲染图片。

### 发给OpenCode

```text
现在完成第 3 步，编写 app/pdf_tools.py。先只实现资料工具，不调用财报模型。

为每份实际 PDF 建立：
1. 原文件快照与 SHA-256。
2. pages.json，每页有 physical_page 和 text。物理第 1 页从封面开始，空白页也保留。不要把 PDF 印刷页码当数组下标。
3. 每个物理页都有的导航卡，包含短摘录、保留位置和省略量。导航是有损索引，不能当完整财务证据。
4. search_fulltext(query, offset)：在整份真实文本中检索字面字符串，返回有限数量的真实页码与上下文。不是只搜目录或预选财务章节。
5. read_pages(pages)：返回指定物理页的完整文本；超过大小限制时报错，不能静默截断。
6. render_pages(pages)：从同一份快照 PDF 渲染真实完整页图，保留表头、单位和所有列，记录图片哈希。优先使用已可用的渲染工具，给 Windows 与本机路径正确的调用方式。

用程序抽查封面、一个中间页和最后一页，验证页数、页码映射和源哈希。搜索词由检查程序自行选取文档中实际存在的一小段，不预设答案页。原生文本不足时明确停止并说明当前未做 OCR。
报告所有工具的输入、输出文件与实际检查结果，记入 project_status.md，然后停下。
```

## 第5步：写出定位、抄录与代码检查

让模型选择证据、按约定抄录，再由程序检查自己的引用。暂时不允许它自行宣布核验通过。

```text
请检查当前项目的启动说明、实际进程、监听地址、端口冲突、服务日志和浏览器报错。确认服务监听本机，并告诉我确切URL；代码有变更时重启必要服务并刷新页面。不要无故重建项目或清空runtime，不发起财报模型调用。
```

### 授权失败或模型不存在

OpenCode 的编码授权和产品后台授权分别核对。

```text
请分别检查编程Agent当前模型、财报程序的服务端模型ID与凭据存在状态，以及同花顺认证。只报告状态与原始错误摘要，不显示密钥。按当前官方文档给出一个明确修复动作。不可用的模型不能自动换名，未配置的外部服务不能用样例数据替代。
```

### 真实运行停在某一步

先确认是程序错误、证据不足，还是服务或预算问题。

```text
请只读最近一次失败任务，报告阶段、失败原因、已有进度、证据路径、累计调用与tokens，以及未知用量。明确哪些是模型自己的引用问题、哪些是程序或服务问题。不要替模型给正确值或页码，不提高阈值，不自动新开任务绕过预算。先给出可核对的诊断。
```

## 交付检查

- [ ] 新增或移除 PDF 后，公司列表随重新扫描变化，排除原因可见。
- [ ] 一次只运行一个任务；刷新、重复点击与切换公司不会重复调用或串结果。
- [ ] 文字原值、单位、页码与引文有留存；没有把整个 PDF 当单次提示词。
- [ ] 视觉会话独立，外部数值私有；文字修改后旧检查失效。
- [ ] 每次续跑都计入同一账本；pending、unknown 与0有区别。
- [ ] 核验通过才生成本轮复盘；失败、历史与当前结果有清楚标记。
- [ ] 至少一次真实运行有完整证据；合成检查与真实通过分开。
- [ ] 换公司或换模型的验证矩阵只填写实际做过的运行。

看到失败先保留证据、读清原因。修复程序可以改变下一版代码；本轮真实数据和检查门槛不能为了通过而改写。
