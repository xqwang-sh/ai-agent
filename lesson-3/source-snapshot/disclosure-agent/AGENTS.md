# 第三讲实作维护

- 项目为金融企业投研团队的巨潮业绩说明会监控Agent。默认从真实公司身份与公告查询开始，不能把已下载材料或教师答案作为默认运行输入。
- 主要模块为cninfo、extract、ledger、runner、schedule。入口为run_agent.py，接口约定见INTERFACES.md。模型负责有证据的分类与提取，程序掌握来源覆盖、事件更新和状态提交。
- 运行时绝不读取teacher-gold或教师参考字段。人工核验标准和模型比较工具在本讲04-tests的日期目录，独立于应用。试验结果不得由人工修正后的输出冒充原模型成绩。
- 凭据只读取进程环境或用户级配置，禁止写入项目、日志、网页、ZIP和Git。所有原始模型尝试、实际模型ID、返回用量及失败均保留，缺用量不能记为零。
- live与replay工作区隔离，实时失败不得静默改为历史成功。过去日期不自动等于实际已召开。只有全部指定查询、处理与关联完成才可报告本轮无变化。
- 源PDF与每次运行证据不可覆盖。相同公告出现新hash时保留版本并复核；事件按原通知锚定，改期不换身份。日期、模型和提取修订分别记录。
- 持续定时配置和真实触发完整流程均为验收项，不能用注册任务或手动启动代替。仅操作本项目的系统任务，平台未实测必须明确标注。
- 先实际比较模型与流程，再写讲义。学员从短业务需求和空任务开始；教师成品、金标准与恢复点分开，不能把完整应用作为学员起点。

- 当前配置明确report_period=2026-Q3，先核验1—2家公司，再在独立工作区扩至全A股且会议日期2026年10—11月，扩围通过后再用相同入口定时。明确的其他报告期在取数/处理时记录排除，不进入活动事件或复核列表；历史原件与测试标准保留。源正文提到往期事项不等于新增事件。
- 全市场分页可能同日排序不稳定，跨页完全重复不能当作公司变更。保持去重ID与来源总数对账，HTTP403/429降低频率并保留未完成，禁止原始行数相同就宣称完整。
- 市场开发预算60、日常配置240次新请求，均含重试纠错，3并发且预留可能的两次尝试；预算不足保留未完成。每次系统触发都刷新来源，不能因为同日积压而复用旧查询冒充当前检查。
- 新默认计划为每天北京时间08:30，周末披露亦检查；已保存旧计划不静默改变，迁移时先停旧业务任务，真实测试新市场入口后才验收。
- 本期核验包分2份起步、8份模板、8份真实变更留出，历史12份独立保留。真实相邻页截止用parts逐页引用，严查页尾到页首，不用单条假quote拼接；原模型结果和首次评分不可覆写。

- 当前产品日历与当天安排仅列会议。提问预征集区间附在同一会议下，只取最新公告中连续、同页且与已核验截止一致的原文；只有截止则仅显示截止。更正更新同一事件并移除旧日期卡片，原公告及变更记录保留。
- 关注名单支持Excel公司简称或股票代码，按巨潮orgId去重，歧义或错配整批拒绝。目录绑定实际运行来源；续跑及来源失败沿用hash核验的市场目录，不能退回合成事件身份。名单在本机保存并作用于所有事件视图；日期内当日更新优先，全部事件仍按日期和时刻倒序。
