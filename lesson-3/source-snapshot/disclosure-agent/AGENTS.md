# 第三讲实作维护

- 项目为金融企业投研团队的巨潮业绩说明会监控Agent。默认从真实公司身份与公告查询开始，不能把已下载材料或教师答案作为默认运行输入。
- 主要模块为cninfo、extract、ledger、runner、schedule。入口为run_agent.py，接口约定见INTERFACES.md。模型负责有证据的分类与提取，程序掌握来源覆盖、事件更新和状态提交。
- 运行时绝不读取teacher-gold或教师参考字段。人工核验标准和模型比较工具在本讲04-tests的日期目录，独立于应用。试验结果不得由人工修正后的输出冒充原模型成绩。
- 凭据只读取进程环境或用户级配置，禁止写入项目、日志、网页、ZIP和Git。所有原始模型尝试、实际模型ID、返回用量及失败均保留，缺用量不能记为零。
- live与replay工作区隔离，实时失败不得静默改为历史成功。过去日期不自动等于实际已召开。只有全部指定查询、处理与关联完成才可报告本轮无变化。
- 源PDF与每次运行证据不可覆盖。相同公告出现新hash时保留版本并复核；事件按原通知锚定，改期不换身份。日期、模型和提取修订分别记录。
- 持续定时配置和真实触发完整流程均为验收项，不能用注册任务或手动启动代替。仅操作本项目的系统任务，平台未实测必须明确标注。
- 先实际比较模型与流程，再写讲义。学员从短业务需求和空任务开始；教师成品、金标准与恢复点分开，不能把完整应用作为学员起点。
