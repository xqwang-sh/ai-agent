# 公告事件智能体

教师参考实现，默认从巨潮真实查询开始。学员从短业务需求和空目录搭建，课堂主线见同级`../lesson3-workshop/lesson.md`。这一成品不进入起步包。

Python 3.11及以上。安装`requirements.txt`后，在本目录运行：

```sh
python3 run_agent.py run
python3 run_agent.py schedule install
python3 run_agent.py schedule test --after-seconds 90
python3 run_agent.py schedule status
python3 run_agent.py schedule pause
python3 run_agent.py schedule resume
```

先手动查对来源、模型结果与事件状态，再安装持续任务。`schedule test`只安排真实系统任务在约90秒后到期；不要用手动`run`冒充定时触发。macOS系统每分钟唤起检查器，新计划默认业务时间为每天北京时间08:30，旧计划按保存的weekdays执行。暂停阻止下次业务运行，系统唤起保留，当前运行继续。电脑醒来仅补当天到时且在计划日内的任务，不补过去日期。

macOS版使用本机用户任务，需要电脑开机且用户登录；关机或退出登录期间不能保证执行。迁到常开位置时须重新验收后台凭据、来源与系统触发。

`config.json`覆盖伊利股份600887、嘉和美康688246，首次回看90天，后续完整成功后回看7天重叠窗口；旧公告按归档原文和模型回执重新核验。默认模型`Qwen/Qwen3.8-27B`来自本次4B、9B、27B比较，使用前核对自己账号模型目录。`config-adaptive.json`是有界规划实验，不是主线。

密钥读取环境变量`SILICONFLOW_API_KEY`，或用户级`~/.config/siliconflow/credentials.env`中的同名变量。Windows用户级配置位于`%APPDATA%/siliconflow/credentials.env`。项目、ZIP和网页都不保存密钥；后台任务必须用本机真实凭据完成一次验证。

默认工作区`runtime/live`，实时与历史重放必须分开。`current.json`提交指针绑定同一轮`runs/<run_id>/state.json`、`summary.json`和`calendar.html`的指纹，使用它恢复状态。根目录同名文件是便捷副本；丢失提交指针时须核对不可变运行后恢复，不能默认为旧副本正确。源PDF、每次模型回执与失败都保留。

结果`complete`表示本轮覆盖与处理完整且无未决事项；`needs_review`表示处理完成但有待判断信息；`incomplete`表示查询或处理未完整完成。CLI后两者返回退出码2，软件异常返回1。定时任务单独记录execution_status和business_status，避免把待复核误报成启动失败。失败不能解释为无新增。

```sh
python3 -m pytest -q
```

测试使用明确标记的模拟数据，不调用付费模型、不安装系统任务。2026年10月30日已实测macOS真实触发、后台巨潮取数及模型调用、暂停恢复。Windows适配只有生成与模拟测试，长期无人值守仍需观察。

运行时不读取候选金标准。本期18份/40页按2份起步、8份新模板、8份真实变更留出分阶段评分；扩围后追加7份/15页只作事后回归，历史12份另行保留。评分保留原始输出；人工修订另存。关键词查询的完整性只适用于指定公司、关键词和日期窗口，不等于所有披露的完整召回。候选金标准待任课教师确认。

产品入口为每轮输出的calendar.html，自包含月历、日期公司列表和事件详情。已有会议用蓝色，当日收录或更新用橙色，截止日用紫色，具体事项按原公告写为提问截止、预报名截止或报名截止；首次回看的旧公告标历史建档，提取校正单独标识。点击日期、公司后可查看时间、摘要、参与说明、变更与原PDF。参与步骤从指纹匹配的原PDF按物理页连续摘录，找不到章节时不补造。

事件activity记录首次收录、实际更新时间、更新类型、修订号和对应运行。重复扫描不刷新；旧记录没有时间则标未知，不按本轮扫描补造。只有疑点变化也会显示更新。来源冲突、未可靠关联的变更和不完整检查会进入复核，暂不生成受影响的提醒；已确认会议与有冲突的截止字段分别判断。

在具体事件详情中可下载该会议及已确认截止的.ics文件，含提前1天、30分钟的DISPLAY提醒，按UTC保存以对应北京时间。文件不含凭据，使用稳定事件UID和递增修订号。导入自己的日历后核对时间与提醒，并确认通知权限。这里交付的是导入快照，不是自动订阅；后续改期或取消，需要检查并更新已经导入的旧提醒，不能承诺自动撤回。

事件详情仅在“公告原文”下列出每份原公告一次，不重复提供“打开最新公告”按钮。日历旁保留当天安排，提醒入口集中在所选事件详情。

当前课堂实作仅监控2026年三季度说明会。先用两家公司建立来源与字段核验，再扩大到全A股、会议日期在2026年10—11月，扩围通过后才配置相同入口的定时任务。半年报和往期事件不进入本次产品。全部事件按会议日期和同日开始时刻倒序；当日更新保留原标签。参与区直接显示完整原文及所有可见网址。历史验证材料和原生运行回执仍按原轮次保留，不代表新扩围已通过。

## 三季度全市场版

先在两家公司上做真实取数、独立字段与原文核验，再使用独立工作区扩大范围。默认业务只收2026年三季度；半年报等及单纯提及旧会议不进入本期日历。合并期别包含本期三季度时保留为一场。

```sh
python3 run_agent.py run --config config-market.json --workspace runtime/market-2026-q3-oct-nov
```

配置的会议窗口为2026年10月1日至11月30日，检索发布起点为2026年1月1日，按沪深北官方身份表核验A股。来源唯一ID、月份及子窗计数分别闭合，异常不转零新增。限流保留原始失败、降频与冷却后续跑。同一轮发现先读完整分页，再在剩余来源请求预算内补同日重复造成的缺口；未补齐仍是未完成。分批队列保存每份原件、模型回执及去向；每批最多60次新模型请求，重试和纠错均计入，模型最多3并发。

未完成的同日手动分批沿用该批来源；`--refresh`显式刷新近期来源。有积压也会检查次日新公告，每次真正系统触发都会刷新。同日已处理完再运行也会刷新，未变原件的模型回答重新核验后复用。页面区分来源实际取得时刻与本次生成时刻，近期查询采用7天重叠，旧月份回执复用不代表全局瞬时快照。

回执已完成而队列尚未提交时，先匹配来源、请求、模型及指纹复核。成功和失败尝试都保留；无完整结果的请求记未知，不能盲目重付。同一原件与模型的每个错误项最多纠正一次；新校验规则产生新的错误项时可作一次针对性纠正，旧错误不能循环重买。跨批服务错误冷却后有限重试，累计最多4次后转人工核验。新公告和明确变更优先，失败前缀不阻塞后续记录。

仅截止句真实跨相邻两页时支持证据`parts`，每段须本页逐字连续、前段到页尾、后段从页首起，中间只可有空白。编号连写或“临”位置可规范比较，原输出保持不变。同ID原件变化先复核，不能被范围外筛选掩盖而继续生成旧提醒。

扩围验收后，才安装`config-market-scheduled.json`的持续任务。它仍是同一业务入口，单次最多240次新请求，含重试纠错；超过预算保留未完成，下次检查先刷新来源再继续。巨潮周末也披露，新的默认计划为每天北京时间08:30，可用`schedule_weekdays`与`schedule_time`明确设置。旧任务已有的计划不会因修改配置而偷偷变更；迁移时先查看并停用旧业务任务，避免双重日常执行。

全市场任务的查看、暂停和恢复使用自己的市场工作区：

```sh
python3 run_agent.py schedule status --config config-market-scheduled.json --workspace runtime/market-2026-q3-oct-nov
python3 run_agent.py schedule pause --config config-market-scheduled.json --workspace runtime/market-2026-q3-oct-nov
python3 run_agent.py schedule resume --config config-market-scheduled.json --workspace runtime/market-2026-q3-oct-nov
```

实际自动更新结果在工作区的`calendar.html`，同一运行的三项产物由`current.json`绑定。讲义的example为另行验证并冻结的展示；它不因刷新网页自动调用API，也不冒充本机实时结果。Windows实机和长期可靠性另验。

明确别期标题按来源口径记录排除。正文用途只确认已绑定财务报告的期别；部分解析出H1而仍有可能的Q3用途时，保留提取或复核，不能据前半句删源。会期排除只使用可核对的单日原文；相对日期、多场、范围或其他潜在目标月份保留待判断，不猜会议日。

提示词升级不抹去原版本。仅`prompts/revalidation-compatibility.json`明确列出的旧提示词、同一Schema与模型配置允许复核复用；原始模型、回执和提示词指纹继续保留。未知提示词或Schema不套用这项兼容。
